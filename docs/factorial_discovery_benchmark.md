# Factorial discovery benchmark

This development controller runs TandemX, TRF and TideHunter on the same complete
observed-read FASTA generated by the streamed factorial simulator. Other task-matched
comparators remain in the broader comparator matrix; these three alone do not
complete the publication comparison. No founder sequences, planted coordinates,
coverage truth or error settings enter the discovery tool commands.

Input verification checks completed development receipts, observed-read/truth
hashes, full FASTA lengths and founder/period consistency. The controller caps
inputs at 100,000 reads and 500 Mb per condition. Genomes/conditions are selected
explicitly; duplicate seeds and held-out generation receipts are refused.

## Endpoints fixed before the first run

- Full-input base precision/recall/F1 uses the union of **all** observed-coordinate
  planted segments, including partial read-end fragments. Raw duplicated predicted
  bases are retained. A prediction on a fragment is not automatically false.
- The eligible-array endpoint requires at least two source founder units, at
  least 100 observed bp and a period in 30–1000 bp. Reads containing any ineligible
  truth segment are excluded from this endpoint by truth alone. Their number and
  all predictions on them are reported. The full-input base endpoint still keeps
  them. This avoids treating genuine short fragments as negative reads or changing
  exclusion based on each tool's predictions.
- Array matching uses maximum-cardinality one-to-one matches, IoU >=0.5 and
  period error <=max(2 bp, round(2% of founder period)). Report recall/precision/F1,
  conditional boundary/period errors, negative-read call rate and union metrics.
  Wilson intervals describe correlated counts; they are not publication inference
  over independent genomes or species.
- Sequence recovery uses all per-array consensuses, deduplicated only by exact
  circular/strand equivalence. TandemX's `candidate_monomers.fa` is used rather
  than its clustered catalogue. Candidate/interval counts must agree. Both all
  planted families and families with observed eligible segments are denominators.
  One-to-one matches require cyclic global Levenshtein similarity >=0.9. This is
  founder recovery, not a biological family definition or family precision.
  Homologous distinct-consensus fraction is reported under its own name.

The independent edlib threshold implementation checks the same rotations/strands
and distance definition as the exhaustive evaluator. Length bounds and early
success avoid computing exact below-threshold similarities; no such identities
are reported. N/N does not count as sequence evidence. Randomized tests compare
the threshold decisions with the previously validated exact edit-distance scorer.

## Commands and receipts

```bash
conda run --no-capture-output -n tandemx-dev python -m benchmarks.scripts.run_factorial_discovery \
  --datasets /path/to/factorial_s6301 \
  --conditions condition_004 condition_006 \
  --trf /path/to/trf --tidehunter /path/to/TideHunter \
  --timeout 900 --outdir /path/to/new/factorial_discovery
pytest -q tests/unit/test_factorial_discovery_truth.py tests/integration/test_stream_quantify.py
```

The example selects 5x clean/high-error development conditions. One thread, one
run per tool/condition; deterministic shuffled tool order. TandemX uses elastic
discovery, sequence clustering at .95, support >=1 and exact-related audit;
TRF uses `2 7 7 80 10 50 1000 -ngs -h`; TideHunter uses format2, periods30–1000,
minimum consensus30 and two copies. These disclosed configurations are not an
equally budgeted tuning study. Output normalization requires span >=100 bp.

`environment.json` stores tool/source/input receipts and parameters; `inputs.tsv`
stores each condition's hashes, actual counts and exclusion/denominator counts.
Every tool retains command/exit/timeout/stdout/stderr plus normalized intervals,
eligible-array details, sequence-recovery assignments and `metrics.json`.
`summary.tsv` combines those values, execution resources and evaluation time.
Errors remain missing and are recorded even when another method succeeds.
`validation.json` distinguishes process/scoring completion from scientific acceptance.
Tool resource measurements exclude evaluator/controller costs; ongoing concurrent
jobs make these diagnostics, not publication rankings.
